# 试听与反馈

## 试听页

`node review_server.mjs` 启动本地页面。页面每次打开都按当前数据重新生成，所以 Agent 改完数据后只需让用户刷新。

页面给用户的能力：

- 逐行点击跳转，播放时逐字高亮，显示注音和译文。
- 每行可以微调时间、把句首定在当前播放位置、采用旧时间或视频时间；整首可以平移。
- 每行可以写备注，这是用户告诉 Agent “这里有问题”的主要途径。
- 每首歌有“通过”按钮，标题旁和最后一行下面各一个。
- 播放条上方有一条固定的导航：“上一处 / 下一处”逐个播放这首歌要听的地方（“这首要听什么”里的按钮和不符合规律的行），同时把对应的行滚到眼前，并把这一行的微调、定在此刻、采用旧时间直接放在导航条上；最右边是“通过，下一首”，标记通过后直接打开下一首没通过的歌并从它的第一处开始播。快捷键 `N` `P` 换一处，`R` 重听，`[` `]` 微调正在听的那一行。用户不需要在顶部的按钮、下面的歌词行和歌曲列表之间来回翻。给一处起名时写上行号（“第 15 行…”），页面靠它找到对应的行。

页面主动替用户做的筛选：

- 需要先听的歌排在最前，并附一句“这首要听什么”和直接跳到可疑位置的按钮。给人看的歌尽量都写上这句话。
- 标签只标真正需要注意的事：时间大幅偏移、置信度低、读音可疑的行数、文件里还是旧版本等。
- 没有任何疑点、读音有来源、听写核对也干净的歌，可以不经试听直接写入；是否启用这条规则由用户决定。
- **和旧轴的关系**：歌词表自带的时间往往只和新轴差一个固定值（歌词表是给同一录音的另一个上传做的）。页面会算出这个值，在歌曲顶部写明“整首比旧轴统一早/晚多少秒”，并只标出不符合这个规律的行，每行旁边有“按规律”的时间可以对比和采用。这样用户听一行确认规律，再看标出来的几行就够了。偏离好几秒的行多半是对齐跳错了位置；不要替用户提前改掉，改了它们就不再被标出来。

## 重排过的草稿怎么交给人

`onepass.py --write` 把已写入的歌重新打轴后，会给它写一段“这首要听什么”，规则是让人听得尽量少：

- 一首歌里有三行以上挪了同样的幅度（相差 0.2 秒以内）算一件事，按钮只给第一行，写明代表几行。
- 挪了 1 秒以上的行逐个列出。
- 工具拿不准的行逐个列出（标记的含义见 [流程与命令](pipeline.md)），一首最多列 6 行，其余只在行上留标记。
- 其余小幅移动只在行上留标记，并写明“不用专门听”；没有要听的就直说。

用户在这样的草稿上只改了很少的行是常态。改得多、或者改的都是同一类（比如句内不实时、重复的句子分不清）时，先查原因：多半是某一路读法没被用上，而不是该逐行手修。

## “通过”的含义

- 用户点了通过，且没有未处理的备注：直接写入。
- Agent 之后只要改动了这首歌的草稿，通过标记自动失效，页面显示“有改动，待重听”。用户自己调时间、写备注不会让标记失效。
- 所以改完一首已通过的歌后有两种结局，由改动大小决定：
  - 按备注做的明确修改（改一个读音、删一行歌曲信息）：改完直接写入。
  - 改动大或带有推断（补了一句、整首重排、歌词按猜测改写）：不写入，退回给用户重听，并写明要听哪里。

## 处理备注

1. 读出所有带备注或已通过的歌，连同备注所在行的现有标注。
2. 逐条归类：确认现有内容、改读音、改歌词文字、删行、缺行、时间问题、不确定。
3. 改读音、改字、删行用 `fix_lines.mjs`。缺行和整首偏移需要整首重排，重排后退回。
4. 备注里的读音和现有一致时不要改。用户用罗马音写读音是常态，按发音理解，不要求拼写规范。
5. 用户说“某一行开始后面都不是歌词”时，先看那一行本身是不是同类内容，再决定从哪一行删起，并在汇报里说明。
6. 用户把某一行手动挪了 1 秒以上时，套用微调之后对这一行跑 `refit_lines.py <key> <行号>`：手动微调只是整句平移，句内的字还留着挪之前的间隔，那是对着别处的声音排的。它保持句首不动，只把句内的字在新位置重新对一遍；结果不合理（句内出现几秒的空档）就保留平移的结果。哼唱、吟唱这类模型听不懂的行用 `--even`，把字在这一句里平均铺开。只动用户这一轮挪过的行和紧挨着的上一行，别的行保持用户通过时的样子。
7. 用户把一行挪到了下一行之后，两行的先后就反了，写入时回读自检会失败。不要自己对调，留在试听页问一句。
8. 处理完清掉该歌的备注，写入，再汇报。

## 听歌时发现问题

仓库里带一个可选的 Folia 插件「歌词送去复查」（`folia-mod/lyrics-review`）：播放时点一下进度条右边的小旗子（命令面板和播放器面板里也有同样的入口），就把当前歌曲和播放位置记到试听页，必要时启动试听服务，并在浏览器里打开到这首歌。被送回的歌不论之前是什么状态都会重新出现在“先听”分组里。

它不在 Folia 的模组市场里，要从本仓库安装。用户用 Folia 并且想要这个功能时，由 Agent 安装：

```text
node install_folia_mod.mjs            # 预览：装到哪里、装哪些文件
node install_folia_mod.mjs --write    # 安装（Folia 的 mods 目录不在默认位置时加 --mods-dir）
```

- 安装前告诉用户要做什么：往 Folia 的插件目录里复制几个文件。同意后再加 `--write`。
- 装完后有一步只能用户自己做：在 Folia 的模组面板里启用它并确认提示。这个插件带一段在 Folia 主进程里运行的代码（用来启动试听服务），Folia 对没有签名的插件会先问用户。
- 插件声明了它核对过的 Folia 版本范围，Folia 更新后超出范围会被拒绝加载。这时不要直接放宽范围：它读取了 Folia 的内部状态（当前播放的歌曲），要先确认新版里这部分没变。
- 工具目录换了位置、或改了试听页端口之后，重新运行一次安装。

## 汇报

每轮结束用清单说明：写入了哪些、每首按备注改了什么、哪些修改是推断（原因和依据）、哪些退回以及要听哪里、哪些备注没能处理和原因。不要让用户自己去比对。
