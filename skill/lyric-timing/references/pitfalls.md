# 常见陷阱

这些问题都实际发生过，并且都不会报错，只会让结果悄悄变差。导入后和结果异常时对照检查。

## 导入歌词时

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 第一句歌词不见了 | 歌词表里第一句和制作信息共用时间零点，被当成制作信息一起删掉 | `dropped_text_scan.mjs` |
| 某行少了一个词 | “原文 译文”写在同一行，拆分时把原文的一部分当成了译文 | 同上 |
| 高亮在某一句里跑得飞快，后面留下一段空白 | 译文或罗马音粘在原文后面，被当成歌词对齐了一遍 | `mixed_translation_scan.mjs`，再用 `fix_lines.mjs` 截掉 |
| 读音检查报出一批怪结果 | 日语歌词里混了简体字，词典查不到 | `fix_simplified_kanji.py` |
| 歌词表自带的注音是错的 | 来源本身就带着机器生成的错误罗马音，被当成“作者给的读音”采用 | 自带注音同样要过上下文判断 |
| 一串汉字只读出最后一个字的音（未来像读成“ぞう”） | 歌词表的括号读音只写了最后一个字的，而括号读音会套到它前面连着的整串汉字上 | 列出所有标在两个以上汉字上的括号读音，和词典读音比对，补成整串的读音 |
| 注音里出现“つずき”这类错字 | 罗马音读音里的 zu、ji 分不出づ和ず、ぢ和じ | 这类读音改用假名写 |
| 括号读音原样显示在歌词里 | 罗马音里带撇号等符号，没被认成读音 | 这类读音改用假名写 |
| 外语句后面的“译文”其实是唱出来的下半句（La la 停不下） | 中外文混排的一句被拆成了原文加译文 | 把译文并回原文、清空译文，再单行重对齐 |
| 译文看着像整体错了一行 | 译者为了中文语序把相邻两句对调了 | 不是配对错误，保持原样 |
| 英文、片假名后面跟着方括号注释（オープンワールド[Open World]） | 歌词表作者加的注解，不是唱的内容 | 从歌词里去掉 |
| 带歌手标签的歌词整行不见了（“甲+乙：歌词”） | 清理制作信息的脚本按“标签：内容”判断，把它当成了制作名单 | 先看 `clean_credits.mjs` 不带 `--write` 的预览；带歌词的行只去标签，再运行清理 |
| 歌名、专辑名、歌手名单、译者说明出现在歌词里 | 它们在歌词表里和歌词格式相同 | 试听时由人指出，或导入后人工扫一眼首尾几行 |
| 空白的歌词行 | 用括号标出的和声、歌手标记被清空但行保留了 | 和声恢复文字，歌手标记删行 |
| 英文后面括号里的片假名被唱了两遍 | 括号里是注释而不是歌词 | 删掉括号部分 |

## 对齐时

- **歌词版本和录音不一致**：现场版多唱一遍、翻唱删了一段、电视版只有一半。对齐不会报错，只会把多出来的行挤进别处。先做版本核对。
- **整首比歌词表晚或早一个固定值**：翻唱和现场版的前奏长度不同。把歌词表时间整体平移后再整首对齐。
- **重复的句子**：副歌可能被对到上一次出现的位置。现象是某一行比歌词表早一整段。
- **符号也可能被唱出来**：手柄按键的圆圈和叉、摩斯电码的点和划。给它们写上读音，否则那一句的句首会偏晚。
- **对不出来的行**：拖长的“啊”、打了码的词、即兴的 Oh，录音里没有可对的发音，会被放到很远的地方，还会把上一句的结尾拉长。用 `pin_to_source.mjs` 放回歌词表的时间，并在备注里请用户听这几处。
- **整首比歌词表统一早或晚**：不是错误。试听页会算出这个固定值并只标出不符合的行（见 [试听与反馈](review.md)）。
- **非日语歌里夹着假名**：按日语发音对齐，不需要另外写读音。
- **重唱的次数**：歌词表只写一遍的短句，录音里可能连唱好几遍。试不同遍数，看哪一种对齐出来的间隔最均匀，并和听写结果互相印证。

## 采用外部来源时

- **同名不同曲**：视频、歌词页都要先比对歌词再用。
- **给没有歌词的翻唱配原唱的歌词**：先打草稿，再用听写核对；翻唱常有多出来的念白或没唱的段落，备注里请用户留意。
- **下载目录里的旧文件**：换了来源视频后，目录里上一个视频的抽帧和读音必须清掉，否则会把别的歌的内容当成这首的。
- **视频的时间只有在它是同一个录音时才能用**，用音频指纹确认。

## 改动已有成果时

- **批量重跑会覆盖人确认过的歌**。重跑和自动写回都必须跳过确认过的歌。
- **整首重排会推翻人听过的时间**，即使只改了一个字。用单行修改。
- **同一时间点有两行**：写入后回读时顺序可能互换，自检会失败。把后一行的开始时间错开一点。
- **两个任务同时改同一首歌**会互相覆盖。后台任务没结束前，不要对它涉及的歌做别的修改。

## 写入之后

- **播放器里还是旧歌词**：多数播放器在导入时把内嵌歌词存进自己的数据库，文件改了也不会自己重读。让用户重新扫描或重新导入文件夹。
- **只有一部分歌是新的**：带注音的歌如果由播放器插件直接从文件读，会是新的；只有普通歌词的歌走播放器的缓存，是旧的。两边对不上时先想到这一点，再去查文件。

## 运行脚本时

- 多数脚本一运行就开始处理全部歌曲。**不要用导入或不带参数运行来测试脚本**；只需要确认语法时用解释器的语法检查。
- 会改写歌词表的脚本需要 `--write`，没有这个参数时只报告不修改。新增这类脚本时保持这个约定。
